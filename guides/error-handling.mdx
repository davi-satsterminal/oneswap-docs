---
title: "Error handling"
description: "How escrow swaps fail, and how to handle it safely."
---

Escrow failures come in two shapes:

1. **Thrown errors** — the SDK throws a plain `Error` whose `message` is the server message. These happen at call time (`createSwap`, `getSwap`, `waitForSwap`) — for example a bad pair, an already-open swap, an invalid key, or a rate limit.
2. **Terminal statuses** — the swap is created successfully but ends in a non-success terminal state (`refunded`, `expired`, `failed`). You read these off the swap's `status`, not from a thrown error.

Because escrow swaps are **atomic DvP**, a swap that does not complete has its input **refunded** — funds are never stranded by a partial swap.

## Thrown errors

The SDK throws a standard `Error`. Inspect `err.message` for the server's message:

```typescript
try {
  const swap = await oneswap.escrow.createSwap({
    userRef: 'user-1042',
    inSymbol: 'CBTC',
    amountIn: 0.01,
    outSymbol: 'HTEST',
  })
} catch (err) {
  console.log((err as Error).message)
}
```

| Message / condition | HTTP | When | What to do |
|---|---|---|---|
| `this user already has an open swap; finish or let it expire first` | — | You called `createSwap` for a `userRef` that already has an open (non-terminal) swap | Resume the existing swap, or wait for it to reach a terminal status / expire before creating another |
| `no pool for IN/OUT` | — | `{ inSymbol, outSymbol }` does not match a visible pool | Fix the symbols, or pick a pair that has a live pool |
| Invalid / missing `x-sdk-key` | `401` | The API key is missing, malformed, or revoked | Check the key and mint a new one if needed |
| Rate limit exceeded | `429` | Too many requests for the key's per-minute tier | Back off and retry (see below) |

## Terminal statuses

A created swap always reaches one of these terminal statuses. Read `status` (and `amountOut` / `senderParty` / `error`) off the swap:

| Status | Meaning | What to do |
|---|---|---|
| `returned` | **Success** — `amountOut` of `outSymbol` was returned to `senderParty` | Record the payout |
| `refunded` | Deposit amount was outside the **1%** tolerance, or output was below `minOut` — the input was returned to the sender | Tell the user; they can try again with the exact amount or a lower `minOut` |
| `expired` | No deposit arrived before `deadline` (60 minutes) — nothing happened | Create a fresh swap if the user still wants to trade |
| `failed` | An unexpected error (rare); `error` is set | Inspect `error`; the input is refunded by the atomic guarantee |

## The "already has an open swap" case

Only one open swap per `userRef` is allowed. When you hit this, don't create a duplicate — look up the swap you already have for that user and resume it:

```typescript
async function createOrResume(args) {
  try {
    return await oneswap.escrow.createSwap(args)
  } catch (err) {
    if ((err as Error).message.includes('already has an open swap')) {
      // Resume the swap you stored against this userRef instead of creating a new one
      const existingId = lookupSwapId(args.userRef)
      return oneswap.escrow.getSwap(existingId)
    }
    throw err
  }
}
```

Store `swap.id` against your `userRef` at creation so you can always find the open swap again.

## Rate limits

Requests beyond a key's per-minute tier return `429`. Create is the tightest tier (1× the key's per-minute limit); polling is 4× the create rate. Back off and retry:

```typescript
async function pollWithBackoff(id: string) {
  let delay = 3000
  for (;;) {
    try {
      return await oneswap.escrow.getSwap(id)
    } catch (err) {
      if ((err as Error).message.toLowerCase().includes('rate')) {
        await new Promise((r) => setTimeout(r, delay))
        delay = Math.min(delay * 2, 30000)
        continue
      }
      throw err
    }
  }
}
```

Prefer `waitForSwap` (or a fixed poll interval) over tight polling loops so you stay under the limit.

## A robust create-and-wait pattern

```typescript
async function runSwap() {
  let swap
  try {
    swap = await oneswap.escrow.createSwap({
      userRef: 'user-1042',
      inSymbol: 'CBTC',
      amountIn: 0.01,
      outSymbol: 'HTEST',
    })
  } catch (err) {
    // Bad pair, already-open swap, auth, or rate limit — no swap was created.
    console.error('Could not create swap:', (err as Error).message)
    return
  }

  // Show the user where to deposit.
  console.log(`Send ${swap.amountIn} ${swap.inSymbol} to ${swap.depositParty} before ${swap.deadline}`)

  const done = await oneswap.escrow.waitForSwap(swap.id)

  switch (done.status) {
    case 'returned':
      console.log(`Returned ${done.amountOut} ${done.outSymbol} to ${done.senderParty}`)
      break
    case 'refunded':
      console.log('Refunded — amount outside tolerance or below minOut. Input returned to sender.')
      break
    case 'expired':
      console.log('No deposit arrived before the deadline. Nothing happened.')
      break
    case 'failed':
      console.log('Unexpected failure:', done.error, '— input is refunded by the atomic guarantee.')
      break
  }
}
```

<Note>
  If `waitForSwap` times out while a swap is still non-terminal, the swap may still settle. Resume
  with `getSwap(id)` rather than treating it as failed. And remember: against a deployment without
  the escrow monitor enabled, a swap stays in `awaiting_deposit` / `deposit_detected` and never
  reaches a terminal status.
</Note>
