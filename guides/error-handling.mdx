Because v2 settles as [atomic DvP](/concepts/atomic-dvp), failure handling is
simple: a swap either fully settles or nothing moves. The SDK throws on failure and
the trader's balance is unchanged.

## Errors throw

Every SDK call rejects with an `Error` whose message carries the reason:

```ts
try {
  await dex.swap(1.0, true, { slippageBps: 50 });
} catch (e) {
  console.error(e.message); // e.g. "…/swap: slippage"
}
```

Common messages:

| Message | Meaning |
|---|---|
| `slippage` | Quote moved beyond your `slippageBps` — re-quote and retry. |
| `amount too small: rounds to zero output` | Input too small for the pool's precision. |
| `insufficient …` | Not enough balance / unlocked holdings. |
| `pool not found` | Bad `poolId`. |
| `not logged in …` | Call `register()` / `login()` / `setSession()` first. |

## Atomic failure = automatic refund

If the on-ledger execute fails, OneSwap withdraws the trader's allocation
server-side — the locked funds return automatically. There is **no** partial state
to clean up. The call throws; the trader's balance is exactly as before.

The only ambiguous case (a lost `execute` response) is resolved from the trader's
on-ledger output balance, never guessed — so you never get a double-pay or a
silent loss.

## Idempotency (safe retries)

Pass an `idempotencyKey` to any fund-moving call. A retry with the same key returns
the original result instead of executing twice — the correct way to handle network
timeouts:

```ts
const key = 'swap-' + orderId;
async function swapWithRetry() {
  for (let i = 0; i < 3; i++) {
    try { return await dex.swap(1.0, true, { idempotencyKey: key }); }
    catch (e) { if (i === 2) throw e; await new Promise(r => setTimeout(r, 1000)); }
  }
}
```

The same key never double-swaps — the second call returns the first result.

## Interactive-flow errors

For [interactive swaps](/guides/interactive-swaps):

- If the user's signature is invalid or the quote moved, `execute` throws — nothing
  settled.
- If the user never calls `execute`, nothing is committed; any allocation created
  during `prepare` is released.
- Always show the `quote` before signing so users aren't surprised by price impact.
