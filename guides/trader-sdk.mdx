---
title: "Trader SDK"
description: "Quote and trade a OneSwap wallet with an administrator-issued Trader SDK key."
---

The Trader SDK lets an existing OneSwap account trade its own wallet over HTTP. It is separate
from the [integrator SDK](/introduction): an integrator key creates deposit-and-return swaps for
other users, while a trader key can move funds only from the wallet bound to that key.

The mainnet API base is:

```text
https://api.oneswap.cc/swapv2
```

Install the typed TypeScript client for a backend service or trading bot:

```bash
npm install @oneswap/trader-sdk
```

## Access model

Trader SDK access is provisioned by the OneSwap team. A trader cannot activate Trader SDK
access or create a key. To get access, send OneSwap the account and wallet you want to trade;
an administrator will approve the account and issue a wallet-bound `tk_live_...` key.

Access remains fail-closed: the issued key, its account, its bound wallet, and the requested
market must all remain approved. OneSwap can revoke the key or account access immediately.

A trader key never accepts a client-supplied `walletId`. The backend resolves its bound wallet
from the key and rechecks ownership on every request.

## Receive your key

OneSwap sends the issued `tk_live_...` key to the approved trader through an agreed secure
channel. Store it immediately and send it as `x-trader-key` on Trader SDK requests. If you
lose or expose it, ask OneSwap to revoke it and issue a replacement.

## List pools and balances

```bash
curl 'https://api.oneswap.cc/swapv2/api/trader/pools' \
  -H 'x-trader-key: tk_live_...'

curl 'https://api.oneswap.cc/swapv2/api/trader/balances' \
  -H 'x-trader-key: tk_live_...'
```

## Quote and swap

Quote before every swap. `xToY: true` pays with the pool's `assetX`; `false` pays with
`assetY`.

```bash
curl -X POST 'https://api.oneswap.cc/swapv2/api/trader/quote' \
  -H 'content-type: application/json' \
  -H 'x-trader-key: tk_live_...' \
  -d '{
    "poolId":"rt-...",
    "amountIn":100,
    "xToY":true,
    "feeMode":"prepaid"
  }'
```

Then submit the swap with a unique idempotency key and a minimum output derived from the quote:

```bash
curl -X POST 'https://api.oneswap.cc/swapv2/api/trader/swap' \
  -H 'content-type: application/json' \
  -H 'x-trader-key: tk_live_...' \
  -H 'idempotency-key: order-1042' \
  -d '{
    "poolId":"rt-...",
    "amountIn":100,
    "xToY":true,
    "minAmountOut":9.9,
    "slippageBps":100,
    "feeMode":"prepaid"
  }'
```

Omitting `feeMode` is equivalent to `"prepaid"` and preserves the ordinary fee path.

With the TypeScript SDK, the same flow is:

```ts
import { TraderSDK } from '@oneswap/trader-sdk'

const trader = new TraderSDK({
  apiKey: process.env.ONESWAP_TRADER_KEY!,
  environment: 'mainnet',
})

const quote = await trader.quote({
  poolId: 'rt-...',
  amountIn: 100,
  xToY: true,
  feeMode: 'prepaid',
})

if (quote.sufficientFunds) {
  await trader.swap({
    poolId: 'rt-...',
    amountIn: 100,
    xToY: true,
    minAmountOut: quote.amountOut * 0.99,
    feeMode: 'prepaid',
    idempotencyKey: 'order-1042',
  })
}
```

Keep a trader key on a server you control. It can execute trades with real wallet funds and
must never be embedded in a browser or mobile application.

## Three-token fees

A trader may explicitly select a third-token network fee by sending `"feeMode":"token"`.
This selection works only when OneSwap has enabled it for both the trader and the requested
market. The trader cannot enable or reconfigure this capability through the SDK.

When it is available, send `feeMode: "token"` to both quote and swap. The quote returns the
fee token, final fee amount, and balance checks. If it is not available, the request fails
without changing the market's fee configuration.

The configured fee instrument must differ from both pool assets. Three-token settlement is
available only on synchronous atomic pools.

### Select it in the quote

```bash
curl -X POST 'https://api.oneswap.cc/swapv2/api/trader/quote' \
  -H 'content-type: application/json' \
  -H 'x-trader-key: tk_live_...' \
  -d '{
    "poolId":"rt-...",
    "amountIn":100,
    "xToY":true,
    "feeMode":"token"
  }'
```

The quote reports the selected fee and authoritative balance checks:

```json
{
  "feeMode": "token",
  "tokenFee": {
    "symbol": "USX",
    "amount": 0.0001,
    "feeWallet": "oneswap-op-...::..."
  },
  "tokenFeeBalance": 2,
  "tokenFeeRequired": 0.0001,
  "sufficientTokenFee": true,
  "sufficientFunds": true
}
```

For Trader SDK requests, the backend derives `tokenFee.amount` from the live Canton traffic
cost, including the additional fee-token allocation. It subtracts OneSwap's measured reward
recovery, applies the trader's existing network-fee promotion, and converts CC → USDCx → the
configured fee token at live prices. The quote includes that calculation:

```json
{
  "tokenFee": {
    "symbol": "USX",
    "amount": 0.0266,
    "pricingMode": "traffic-converted",
    "grossTrafficCc": 1.333333,
    "recoveryFraction": 0.8,
    "networkMultiplier": 1,
    "netTrafficCc": 0.266667,
    "ccPriceUsdcx": 0.1,
    "feeTokenPriceUsdcx": 1,
    "usdcxCost": 0.0266667,
    "promotionalWaiver": false
  }
}
```

A 100% network-fee promotion returns `amount: 0` and `promotionalWaiver: true`. The swap
still executes, but the atomic settlement omits the fee-token transfer. Traders without that
promotion pay the converted amount in the final quote.

Pass the same `feeMode: "token"` to `/api/trader/swap`. The swap input, output, and fee-token
leg, when charged, settle atomically. If any leg fails, none of them settle.

The TypeScript SDK exposes the same selection as `feeMode: 'token'` on `quote()` and `swap()`.

<Warning>
  Never switch fee modes between quote and swap. Build `minAmountOut` from a quote using the
  same `poolId`, direction, amount, and `feeMode` as the submitted swap.
</Warning>

## Other endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/trader/tokens` | Registered tokens |
| `GET` | `/api/trader/swaps` | History for the key's bound wallet |
| `GET` | `/api/trader/intent/:id` | Status of an asynchronous intent |

## Disable access

Contact OneSwap to revoke a key, disable Trader SDK access, or disable three-token selection.
Existing keys stop working on their next request after access is revoked.
