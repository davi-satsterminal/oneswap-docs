# OneSwap SDK

OneSwap is an atomic delivery-versus-payment (DvP) DEX on the **Canton Network**. The SDK lets you embed token swaps into your own app for your end-users.

Today the SDK exposes exactly one capability: **escrow swaps**.

```typescript
import { OneSwap } from '@oneswap/sdk'

const oneswap = new OneSwap({ apiKey: 'sk_live_...' })

// 1. Create an escrow swap for your end-user
const swap = await oneswap.escrow.createSwap({
  userRef: 'user-1042',
  inSymbol: 'CBTC',
  amountIn: 0.01,
  outSymbol: 'HTEST',
})

// 2. Tell the user to send `amountIn` of `inSymbol` to this Canton party
console.log(swap.depositParty)

// 3. Wait for OneSwap to detect the deposit, swap, and return the output
const done = await oneswap.escrow.waitForSwap(swap.id)
if (done.status === 'returned') {
  console.log(`Returned ${done.amountOut} ${done.outSymbol} to ${done.senderParty}`)
}
```

## What escrow swaps are

Escrow swaps are built for integrators who want to offer token swaps to end-users whose wallets **can only make a plain fund transfer** — they cannot sign a Canton DvP transaction themselves.

Instead of asking the user to co-sign anything, you hand them a Canton party id to send funds to. OneSwap detects the deposit, performs the swap custodially and atomically, and returns the output token **to the party that funded the swap** (return-to-sender).

## How it works

1. Your backend calls `createSwap` and gets back a per-user `depositParty` (a Canton party id) and a `deadline`.
2. You tell your end-user to send `amountIn` of `inSymbol` to `depositParty`.
3. OneSwap detects the deposit, performs the atomic swap, and returns the output token to the **depositing** party.
4. You poll `getSwap` (or await `waitForSwap`) until the swap reaches a terminal status.

Because the swap is atomic DvP, it either completes and returns the output token or the input is refunded — funds are never left stranded by a partial swap.

## Who it's for

- Apps and wallets whose users can transfer tokens but cannot sign a Canton DvP transaction.
- Integrators who want a swap embedded in their product without building settlement logic.
- Any backend that can call an HTTP API and hold a stable id for each of its users.

<Note>
  **Availability.** Escrow settlement is processed by a background monitor that is enabled
  per-deployment. Escrow swaps are live on OneSwap **devnet** today; **mainnet** access is
  enabled per integrator — reach out to get provisioned. A swap created against a deployment
  without the monitor stays in `awaiting_deposit` / `deposit_detected` and never settles.
</Note>

## What you get

- **Escrow swaps** — create a swap, hand the user a deposit party, poll to completion.
- **Return-to-sender** — output is always paid back to the party that funded the swap.
- **Atomic DvP** — the swap completes and returns output, or the input is refunded.
- **No gas for your users** — the per-swap network fee is taken from the input token, so the end-user's wallet needs no CC.
